# AppReseal

[中文](README.md) | [English](README.en.md) | 日本語

自分または小さなチームで使う、Apple アプリの復号ツールです。App Store のアプリを選ぶと、サーバーが暗号化パッケージを自動でダウンロードし、自動で復号します。終わったら平文パッケージをダウンロードします。手元の暗号化 IPA をアップロードすることもできます。

利用者が自分で脱獄端末を用意する必要はない。ウォレット、価格、チャージはない。

![ホーム](docs/screenshots/home.png)

**免責事項：本プロジェクトは学習と研究のみを目的とする。** 解析する権利のあるパッケージだけを扱うこと。海賊版の配布、課金の回避、その他の違法な用途には使わないこと。

画面の表示は現在中国語です。操作名は画面に出る表記のまま書き、括弧で日本語を添えます。

## できること

- App Store からアプリを選んで処理を依頼できる。自分の暗号化 IPA をアップロードすることもできる。
- 大きいファイルは進捗が表示され、中断しても続きから送れる。最初からやり直す必要はない。
- 完了後は短時間だけ有効なリンクでダウンロードする。中断からの再開に対応している。
- 待ち行列にある処理も、実行中の処理もキャンセルできる。キャンセルは処理を止めるだけで、返金はない。
- 管理画面で Apple ID のプール、チームアカウント、ストレージの整理を扱える。
- 一般ユーザーにはサーバーのパス、アカウント、スクリプト名は見えない。これらは管理者だけが見られる。

デモのアプリ、開発者、パッケージ名、アカウントはすべて架空です。実際に復号するには、自分で Apple ID と 16 バイトの `credential.bin` を用意する。

## インストール

Docker Desktop と、イメージや依存関係を取るための外部ネットワークが必要です。初回のビルドでは復号エンジンをコンパイルするため、数分かかることがある。

```bash
git clone <リポジトリの URL> appreseal
cd appreseal
docker compose up -d --build
```

[http://127.0.0.1:8088](http://127.0.0.1:8088) を開く。

| 役割 | メール | パスワード |
| --- | --- | --- |
| 一般ユーザー | `demo@appreseal.com` | `demo1234` |
| 管理者 | `admin@appreseal.com` | `admin1234` |

停止するとき:

```bash
docker compose down
```

データは Docker ボリュームにある。`docker compose down -v` はデータベースとアップロードファイルも消す。

### 他人に使わせる前に

`docker-compose.yml` のデータベースパスワードと `APPRESEAL_JWT_SECRET` は手元のデモ用です。公開する前に必ず変え、HTTPS を付ける。

## 使い方

### 1. Apple ID を用意する

1. 管理者でログインし、「Apple ID 池」（Apple ID プール）を開く。
2. 「登录 Apple ID」（Apple ID にログイン）を押し、ストアを選んでパスワードを入れる。二要素認証が出たら、6 桁のコードを追加する。
3. 下の手順で `credential.bin` を用意し、「导入凭证」（認証情報をインポート）からアップロードする。ファイルはちょうど 16 バイトでなければならない。
4. アカウントにストアを付け、有効のままにする。

#### `credential.bin` の入手

入手方法は、上流の [fairplay-decrypt](https://github.com/EthanArbuckle/fairplay-decrypt) を参照する。このリポジトリに同梱されている [`backend/docker/fairplay/fairplay-decrypt`](backend/docker/fairplay/fairplay-decrypt) は復号だけを行う。このサイトに生成ボタンはない。

`decrypt.py` は `--credential` で、すでに保存してある認証情報を読む。既定のパスはそのディレクトリの `credential.bin` です。長さがちょうど 16 バイトでなければ実行を拒む。同じディレクトリに書き出し用や生成用のスクリプトはなく、Apple ID へのログインでもこのファイルは作られない。`fairplay-tools/appget.sh` の `account credential <メール> <パス>` は、用意済みのファイルをアカウントへ結び付けるだけです。

16 バイトのファイルができたら、管理画面の「Apple ID 池」からインポートする。サービスはメールアドレスごとに、データボリュームの `creds/<メール>/credential.bin` へ保存する。パスワードは一緒に保存しない。

新規処理では、使えるアカウントがあるストアしか選べない。アップロードした IPA も、プール内のいずれかの `credential.bin` で解けなければ失敗し、料金は戻る。

これらのファイルはデータボリューム `/app/data/ipatool` にだけ置く。Git には入れない。

### 2. 処理を依頼する

一般ユーザーでログインし、「新建脱壳」を開く。

- **App Store のアプリ:** ストアを選び、アプリを検索してタスクを送る。料金は引かれない。
- **IPA のアップロード:** `.ipa` を選ぶか、ドラッグして入れる。進捗が表示される。通信が切れても、同じファイルでもう一度「确认下单」（注文を確定）を押せば、前回の位置から続く。

完了したら詳細ページからダウンロードする。リンクは 15 分間有効で、中断からの再開に対応している。

処理を止めたいときは「取消任务」（タスクをキャンセル）を押す。サービスはそのとき起動したプロセスを止める。

### 3. 完成品の市場

ホームと「成品库」にある完成品は、すでに整理済みのパッケージです。ログイン後はそのままダウンロードできる。購入も無料期間もない。

### 4. ストレージ

管理者は「系统设置 → 存储与清理」（システム設定 → ストレージとクリーンアップ）でディスク使用量を見て、保存期間を変えられる。既定では成果物を 30 日、失敗した処理のアップロードを 14 日、処理ログを 90 日残す。期限が来るとファイルは消えるが、処理の記録は残る。詳細ページには成果物の期限切れと出る。

## ローカル開発

Docker を使わない場合は、フロントエンドとバックエンドを別々に起動できる。バックエンドは既定で H2 のファイルデータベースを使い、実行部は模擬です。実際のダウンロードや復号はしない。

```bash
# バックエンド。JDK 21 が必要
cd backend
./mvnw spring-boot:run

# フロントエンド。Node.js 20 以降が必要
cd frontend
npm install
npm run dev
```

フロントエンドの開発用アドレスは [http://127.0.0.1:5173](http://127.0.0.1:5173) です。本物の API に繋ぐとき:

```bash
VITE_API_MODE=real VITE_API_BASE=http://127.0.0.1:8080/api/v1 npm run dev
```

## よく使う設定

これらの変数は `docker-compose.yml` の `backend.environment` に書く。

| 変数 | 役割 |
| --- | --- |
| `APPRESEAL_JWT_SECRET` | ログイントークンの秘密鍵。32 バイト以上。公開時は必ず変える |
| `APPRESEAL_SEED` | 空のデータベースへデモのユーザーとアプリを入れるか |
| `APPRESEAL_EXECUTOR_MODE` | `shell` はイメージ内の実スクリプトを呼ぶ。`mock` は進捗だけを模擬する |
| `APPRESEAL_DOWNLOAD_LINK_TTL_MINUTES` | ダウンロードリンクの有効期限。既定は 15 分 |
| `APPRESEAL_MAIL_ENABLED` | 有効にすると、パスワード再設定メールを送れる |
| `APPRESEAL_MAIL_HOST` / `USERNAME` / `PASSWORD` / `FROM` | SMTP。587 は STARTTLS。465 のときは `APPRESEAL_MAIL_SSL` を `true` にする |

SMTP を設定していないとき、パスワード再設定は「現在使えない」と明示する。送信したふりはしない。

## コミットしないファイル

リポジトリはこれらのパスを無視している。実行時のデータであり、ソースではない。

- `*.ipa`
- `credential.bin`
- `*.session`、cookie、`.ipatool-passphrase`
- `backend/data/` と Docker のデータボリューム
